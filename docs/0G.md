# Credit check on 0G Private Computer

Noren's pay-later credit line needs a credit decision before the Robinhood-side signer issues its EIP-712 `CreditAttestation` to `NorenCredit`. That credit check runs on **0G Private Computer** as sealed inference: the wallet-history features go to **0GM-1.0** inside an Intel TDX enclave with TEE GPUs. The model returns a tier, a limit, a collateral ratio and a short plain-language rationale. Noren keeps the decision, the 0G request ID and the verification evidence. It does not keep the history.

**What breaks without 0G:** without 0G there is no credit decision, so no credit line can open. The package has no fallback scorer and refuses instead. The alternative would be sending a customer's full financial profile to an AI provider that can read it.

Code: [`packages/ai-underwriter`](../packages/ai-underwriter). Port block 8740-8749.

## Flow

```
customer wallet ──► Robinhood underwriter (packages/robinhood/underwriter)
                    readWalletHistory(): account age, tx count, Stock Token holdings at Chainlink prices, repayment record
                         │
                         ▼  featuresFromHistory(): numbers only, no address
                    @noren/ai-underwriter  creditCheck()
                         │  POST https://router-api.0g.ai/v1/chat/completions
                         │  X-0G-Provider-Trust-Mode: private   (TeeML providers only; the Router never falls back)
                         │  model 0gm-1.0-35b-a3b, verify_tee: true, response_format json_schema (strict), temperature 0
                         ▼
                    0GM-1.0 in a TDX enclave ──► JSON decision + x_0g_trace { request_id, provider, tee_verified }
                         │
                         ▼  checks, in order (any failure → status "refused", no terms):
                         1. tee_verified === true (the Router checked the enclave signature)
                         2. independent check: InferenceServing.getService(provider) on 0G mainnet → TeeML, signer acknowledged;
                            GET {provider}/v1/proxy/signature/{ZG-Res-Key} → EIP-191 signature recovers to the TEE signer;
                            GET {provider}/v1/quote → TDX report_data commits to that same signer address
                         3. strict schema (exact keys, integer ranges, no address in the rationale)
                         4. policy caps (below)
                         ▼
                    { status: approved | declined | refused, terms, evidence, decisionDigest, featuresSha256 }
                         │
                         ▼
                    Robinhood signer signs CreditAttestation(tier, limitUsdg, collateralRatioBps)
                    and logs attestationLogEntry(): zgRequestId, zgProvider, zgChatId, decisionDigest
```

`decisionDigest = keccak256(canonical JSON of {zgRequestId, zgProvider, zgChatId, model, tier, limitUsdg, collateralRatioBps, featuresSha256})`. It ties the signed terms to one 0G inference. The `CreditAttestation` struct is fixed by `NorenCredit`, so the request ID goes in the signer's log and the HTTP response, not in the signed struct.

## Policy caps (the model can't exceed them)

The model gets the caps in its prompt, and `enforcePolicy()` checks them again. A decision outside a cap is **refused, never clamped**.

| Tier | Limit (USDG) | Collateral ratio |
|---|---|---|
| 0 | 0 (declined) | 0 |
| 1 | 1 to 500 | 15000 to 30000 bps |
| 2 | 1 to 2,000 | 14000 to 30000 bps |
| 3 | 1 to 5,000 | 13000 to 30000 bps |
| 4 | 1 to 10,000 | 12500 to 30000 bps |

These rules lower the tier ceiling:
- A past liquidation caps the tier at 1.
- An account younger than 7 days caps the tier at 1.
- Missing data (account age or holdings unavailable) caps the tier at 2.

The ratio never goes below `NorenCredit.minCollateralRatioBps()` (12000 on the deployed config; it can be overridden with `contractMinCollateralBps`). The limit caps match the ceiling of the deterministic scorer in the Robinhood underwriter.

## Privacy model

- **What 0G sees:** account age in days, tx count, whole-dollar holdings by symbol, and repayment counts. The wallet address is never sent: `validateFeatures` rejects an `address` field, a test checks that the prompt contains no address, and the schema rejects a rationale that contains one.
- **Sealed inference:** the private trust tier routes only to TeeML providers. The model runs inside the enclave, the prompt enters encrypted, and the response is signed inside the enclave. 0G's docs say neither 0G nor the hardware operator can see the data. If no TeeML provider is available, the Router returns 503 `no_provider_for_trust_mode` instead of downgrading. We send the header on every request, so a key that isn't in private mode still can't reach a non-TeeML provider. Creating the key in private mode enforces the same rule on the 0G side.
- **Retention at 0G:** the Router keeps billing metadata only (request ID, wallet, model, provider, token counts, trust tier, cost). It doesn't store prompts or completions ([0G privacy docs](https://docs.0g.ai/developer-hub/building-on-0g/compute-network/router/privacy)).
- **Retention at Noren:** `data/decisions.jsonl` stores the decision, the evidence and `featuresSha256`, never the features. A test checks the stored line has no holdings or account fields.
- **TEE scope:** this is a hardware trust assumption (Intel TDX + NVIDIA GPU attestation via dstack), not cryptography over the data.
- **Model choice:** we pin 0GM-1.0. As of Nov 6 the live catalogue also lists `glm-5.3`, `laya` and `0gm-1.0-35b-a3b-sia` as TeeML. Models without TeeML (Claude, GPT, DeepSeek and others) are TeeTLS or standard, where the upstream provider sees the prompt.

## Verification data 0G returns, and what we surface

| Evidence | Source | Where it shows up |
|---|---|---|
| `request_id` | `x_0g_trace` on every response | `evidence.requestId`, the signer's log, `/v1/decisions` |
| serving provider | `x_0g_trace.provider` | `evidence.provider` |
| Router TEE check | `x_0g_trace.tee_verified` (set because we send `verify_tee: true`) | `evidence.teeVerified`; must be `true` or the check refuses |
| chat ID the enclave signed | `ZG-Res-Key` response header | `evidence.chatId` |
| exact cost | `x_0g_trace.billing.*_cost` (neuron) | `evidence.billingNeuron` |
| provider record | `InferenceServing.getService()` at `0x47340d900bdFec2BD393c626E12ea0656F938d84`, 0G mainnet (chain 16661) | `evidence.independent.service` (verifiability, TEE signer, image digest) |
| enclave signature | `{provider url}/v1/proxy/signature/{chatID}` | `evidence.independent.signature.signatureValid` |
| TDX quote | `{provider url}/v1/quote` | `evidence.independent.quote`: `quoteSha256`, and `bindsSigner` (report_data equals the on-chain signer) |

Full Intel-chain verification of the quote is `dstack-verifier`'s job; we record the quote hash for it. If the independent check reports `failed`, the credit check refuses. If one leg can't run (`partial`), for example because the signature endpoint is down, the decision stands on the Router's `tee_verified: true` and is labelled `partial`.

## Setup (Nick)

1. Sign up at https://pc.0g.ai and deposit a small amount of 0G. 0GM-1.0 costs $0.08 per 1M input tokens and $0.48 per 1M output tokens; one check is about 1k tokens.
2. Go to Dashboard → API Keys, create a key, and set its trust mode to **Private**.
3. Put it in the gitignored `packages/ai-underwriter/.env` (or the repo root `.env`) as `ZG_PC_API_KEY=sk-…`.
4. Run `pnpm --filter @noren/ai-underwriter test:live`.

Without the key, every check returns `Setup required: ZG_PC_API_KEY …` (HTTP 503). A rejected key or an empty balance also returns `Setup required`.

## Paying with the customer's own 0G credits (iAI)

The [iAI docs](https://iai.finance/docs) describe staking iAI to get daily compute credits for 0G Private Computer and the 0G App. As of Nov 6 they document no OAuth, sign-in or delegated-spend API that a third-party app could use, so "Sign in with 0G" is **not built**, and we don't claim it.

The honest version that exists today: a customer can send their own Private Computer `sk-` key in the `X-0G-User-Key` header. That one check is then billed to their 0G balance, which can be funded with iAI credits, and `evidence.billingNeuron` shows exactly what it cost them. The key is used for that one request only and is never stored or logged.

## Calling it from the Robinhood signer

```ts
import { creditCheck, featuresFromHistory, attestationLogEntry } from '@noren/ai-underwriter'

const history = await readWalletHistory(borrower)
const check = await creditCheck(featuresFromHistory(history))
if (check.status === 'refused') throw new Error(check.reason)             // no fallback decision
if (check.status === 'declined') return { declined: true, reason: check.decision.rationale, zg: attestationLogEntry(check) }
const signed = await signAttestation({ borrower, score: { ...scoreWallet(history), ...check.terms }, credit, chainId, publicClient })
console.log(JSON.stringify({ nonce: signed.attestation.nonce.toString(), ...attestationLogEntry(check) }))
```

`check.terms` uses the attestation's units: `limitUsdg` in USDG base units (6 decimals) and `collateralRatioBps` as a `uint16`. To use it, add `"@noren/ai-underwriter": "workspace:*"` to the dependencies in `packages/robinhood/package.json`.
